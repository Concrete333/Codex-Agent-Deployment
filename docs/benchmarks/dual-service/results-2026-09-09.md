# Independent-component repair results — 9 September 2026

One custom task: repair an independent CSV importer and retry scheduler, with
fixed interfaces and thirty external acceptance tests. The coordinator was
Astra High in every condition. Run order was B, C, A, one trial each.

All three passed. Solo was cheapest; delegation did not earn back its overhead
on this task. The skill selected a cheaper worker, but did not lower team cost.

Total trial estimate: **$4.093076**. Each passed the fixed acceptance checks, so
its trial cost is also its observed cost per accepted result. B cost 63.6% more
than A; C cost 66.0% more. Separate ownership made delegation possible, not
necessarily economical. No routing-policy change follows from this single task.

Both delegation runs assigned the importer to one worker and handled retry
scheduling in the coordinator. B used a full-history fork inheriting Astra High.
C explicitly selected Astra at low effort and started without inherited history.
The rollouts confirm the effective worker configurations.

C's worker estimate was 30.4% lower, but its coordinator cost more. The whole
skill-enabled run cost 1.4% more than unguided delegation. Those observations do
not establish that the skill caused either difference: there is only one sample
per condition, effort and inherited context changed together, and cache state
was not controlled. Fewer raw tokens did not mean lower estimated cost because
the cached/uncached mix also differed.

## Controls and accounting

- Codex CLI 0.153.4; root model `gpt-6-astra`, effort `high` throughout.
- Fresh task copies share Git tree `742f90c101eb27618769214556c88619020e1f52`.
- B/C have the same optional native GPT worker pool and two-child concurrency
  ceiling. Claude is excluded equally. A disables delegation.
- Personal skill catalogues, memory, plugins and web search are disabled. The
  shared global instructions remain present, as in the first pilot.
- C successfully read the copied skill and model-selection guide. No research
  documents were supplied. A/B were not supplied the deployment policy.
- The reference passes all thirty external tests; the seeded source fails.
  Graders live outside the task checkout. Workers must not inspect them, but
  filesystem read restrictions are not an adversarial secrecy guarantee.
- Worker usage is added to root usage, once per thread. B's fork contains copied
  history, but its token counters start with its own requests after spawning.
  Root CLI usage alone excludes the worker totals shown above.
- Neither B nor C called a collaboration wait, status-list or interruption tool.
  Each worker finished while its coordinator was doing independent work. The
  25-minute wait settings were configured but their behavior was not exercised.
- All three finished within the fifteen-minute safety limit. Recorded wall times
  were A 389.46s, B 353.59s and C 409.05s. Time was not the optimization target.

The fixed checks are the acceptance criterion for this comparison, not proof of
complete correctness. Each run also wrote its own regression tests. Their test
counts differ and are not comparable accuracy scores. C reported a rejected
bytecode-cache cleanup; it completed the repair and passed external grading.

## Prices and limitations

Standard [Astra API prices](https://developers.openai.com/api/docs/models/gpt-6-astra),
checked on 9 September 2026: $10/M uncached input, $1/M cached input, $12.50/M
cache writes and $50/M output. Both effort settings use these token rates.
All recorded cache-write counts are zero. No fast-tier multiplier is assumed;
recorded service tier is null. The largest single input was 36,224 tokens, below
the long-context price threshold. Reasoning output is already included in output.

`estimate = ((input - cached - writes) * 10 + cached * 1 + writes * 12.5 + output * 50) / 1,000,000`

These are API-equivalent estimates, not subscription charges or Codex allowance
measurements. Benchmark preparation, external grading and this supervising
conversation are excluded from the trial totals. No failed paid setup attempts
preceded this task. Model aliases and uncontrolled cache state limit replication.

Thirty tests on one task do not establish a general success rate. This task
allows independent edits but does not require large-repository exploration.
It provides no comparison of Luna, Sol or Claude workers, and no polling result.
Repeat conditions on multiple tasks before revising the routing policy.
