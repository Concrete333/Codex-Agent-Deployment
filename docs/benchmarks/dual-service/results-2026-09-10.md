# Revised-skill repeat — 10 September 2026

One additional C run on the same independent-component repair task. This is
**C2**, using the revised worker policy; A, B and C1 are the saved trials from
[9 September](results-2026-09-09.md), not new runs.

## Setup

The starting task tree, user prompt, runtime configuration, disabled-skill list
and shared global instructions match C1. Codex CLI remains 0.153.4. The root is
Astra High, with a fifteen-minute process limit and the same thirty external
acceptance tests. Each run gets a fresh task copy.

The supplied policy files changed. C2 restricts workers to Luna, Terra, Sol and
Opus 5, keeps Astra-level work with the coordinator, and requires delegation to
remove enough coordinator work to justify handoff and review. Claude remains
disabled by the shared trial prompt, so this run tests only the GPT portion of
the revised policy. The runtime still exposes the same GPT pool; the skill, not
a changed tool configuration, excludes Astra workers.

C2 selected Terra Max for retry scheduling and kept the CSV importer local.
C1 assigned the importer to Astra Light and kept retry scheduling local. Both
used one worker without inherited history. C2's effective configurations are
confirmed in the rollouts; it successfully read the revised policy and guide.

## Waiting behavior

The coordinator issued **19 `clock.sleep` calls**, requesting 10–45 seconds
each, instead of using a collaboration wait. No `wait_agent` call occurred.
The configured 1,500,000 ms collaboration-wait settings did not prevent this
different short-sleep path. The trace establishes the behavior, not why the
model chose it or whether a collaboration-wait tool was available to it.

The model responses issuing those sleep calls account for:

| Input | Cached input | Output | Estimated cost |
| ---: | ---: | ---: | ---: |
| 496,671 | 489,088 | 2,137 | $0.671768 |

That is **67.1% of parent input** and **43.9% of parent estimated cost**. Each
sleep call was matched to its following `token_usage_record`, deduplicated by
response ID. These costs include the reasoning/commentary in those responses;
they are not a charge for wall-clock sleeping. They are already included in the
team total, not an additional cost to add.

Sleeping was substantial but did not explain the entire result. Terra generated
37,596 output tokens, needed corrections, and did not finish the correction
within the shared time limit. Subtracting sleep-response cost would not measure
the counterfactual outcome of a better waiting strategy or prove acceptance.

## Accounting and interpretation

Add the final coordinator and worker counters once per thread. Use the same
standard API-price basis as the earlier trials: Astra $10/M uncached input,
$1/M cached input and $50/M output; Terra $2/M uncached input, $0.20/M cached
input and $12/M output. Sources: the [captured rates](../../model-performance-comparison.md#captured-api-token-rates)
and the official [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)
and [Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra) model pages
checked during preparation. Reasoning output is included in output, not added
again. Both agents report zero cache-write tokens and null service tier; no
fast-tier multiplier is assumed. Maximum individual inputs were 32,286 for
Astra and 61,987 for Terra, below the long-context pricing threshold.

The latest `token_usage_record.thread_token_usage` and `token_count` cumulative
counters reconcile for both threads. Terra has two turn contexts, both Max;
its cumulative thread total includes the initial attempt and correction.

These are API-equivalent estimates, not subscription charges or allowance
measurements. The supervising conversation, experiment preparation and external
grading are outside the trial totals. No paid preflight attempt preceded C2.

This repeat changes several policy instructions together, not just the worker
model. The worker also owns a different component. Differences therefore cannot
be attributed to Terra alone, shortening the guide alone, or the prohibition on
Astra workers alone. Cache state and sampling were not controlled; model aliases
are not immutable snapshots. Reusing one task provides development feedback, not
an independent holdout evaluation or a general success-rate estimate.

This run does not demonstrate savings from the revised skill. Before another
model-routing comparison, verify that waiting can suspend the coordinator
without repeated model turns, and strengthen the evaluation's coverage of
timezone-sensitive scheduling. A fifteen-minute safety limit also constrains a
slower worker; this is a bounded-workflow result, not proof that Terra could not
eventually complete the task. No operational skill changes were made during
this trial.
