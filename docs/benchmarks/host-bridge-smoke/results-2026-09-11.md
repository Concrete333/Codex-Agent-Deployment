## Method and earlier failures

`experiment.py` creates an isolated checkout from `task/`, freezes the request and source hashes, arms the host, probes the real Windows sandbox boundary, then triggers either an offline fake worker or (with `--live`) one Luna Max worker. It does not retry model failures. The fake-worker transport passed before the live call. The final offline suite has 79 passing tests.

Two earlier fake-worker attempts failed without launching a model: Windows packaged-app aliases broke a string-only path comparison; then a sandbox-created trigger was unreadable by the host. Directory-identity checks and a host-created in-place trigger slot fixed these. The slot publishes its commit byte only after its payload is flushed. No ACLs or authentication settings were changed.

## Limits and next comparison

This tiny task is a runtime smoke test, not evidence that delegation is economical. The worker independently ran the final test and attempted unnecessary Python-cache cleanup; two cleanup commands were blocked by policy. It eventually completed without a coordinator correction. That extra work and its token volume belong in the next efficiency analysis, not in a savings claim.

The bridge freezes launch fields, not every checkout byte. It assumes trusted cooperative ownership; checkpoint hashes cannot prevent malicious changes followed by restoration. Recorded process cleanup is not proof that every detached descendant stopped. Compare the same held-out task and worker configuration with native versus software-managed completion, including coordinator setup, review and corrections in total cost through acceptance.
