# Inventory-event comparison: both accepted

The Luna Max component owner and Astra High solo baseline both passed the
frozen checks and original orchestrator's read-only source review. No correction
session or implementation edit was needed during acceptance. Luna's implementation
cost was **94.49% lower**, leaving **$0.732967** for additional deployment overhead
before that advantage disappears. Per-arm cost through acceptance is not measured:
the review was joint and its cost cannot be reliably allocated between arms.

## Implementation results

| Historical API-equivalent cost | $0.775724 | $0.042757 |
| Responses | 5 | 9 |
| Input tokens, including cached input | 80,526 | 211,673 |

Model/effort were verified in every participant turn context and native usage
reconciled. Both ran the same native CLI controls, assignment, structured handoff,
source and 1,800-second limit. Neither spawned children. Solo ran first; the host
then launched the worker and checks without waking a coordinating model. The
outer task ended after launch and returned on the user's review request.

Luna consumed about 2.63 times the input tokens and 3.50 times the output tokens.
Its saving came from the frozen per-token price difference, not reduced token
use. More code and more test methods do not independently establish correctness
or higher review cost. No accuracy ranking between these models follows from
both passing one fixture.

## Acceptance evidence

The original Astra High orchestrator read each arm's engine, ledger, API and
added tests against SPEC.md and inspected the protected projection. It verified:

- Validation precedes replay lookup, resource effects are staged, and failed
  events or iterator exceptions cannot commit partial stock/holds/replay state.
- Holds respect tenant/SKU availability; release, ship, transfer and hold-ID
  reuse preserve the specified quantities and identities.
- Replay compares the event contents independently of dict key order, uses
  original sequence numbers, and cannot alias mutable input or returned receipts.
- Preview uses the same apply implementation with dry_run=True. Snapshot uses
  the supplied project helper. API validates before dispatch and returns the
  selected method's result unchanged.

No material contract defect or unresolved operational judgment call was found.
Handoff notes that external checks were not run by participants are resolved by
the host's saved passing receipts. All reported artifacts remain present and
match checked hashes; protected files, scope and the frozen source/grader remain
unchanged. The host ownership claim is released. No unchanged tests were rerun
for this review and neither implementation was edited.

Acceptance is against this single-process, standard-library contract, not
unlimited proof or coverage of arbitrary custom callbacks and production loads.
The fixture was new to participants, but shares reservation concepts with our
earlier synthetic task. The reference qualified the checker before execution;
it was not supplied to participants or used as their output oracle. The Sol
fixture audit and its five pre-freeze coverage corrections are documented in
[the audit note](fixture-audit-2026-09-12.md).

The joint review already costs more than the implementation-price difference,
but it covers **both** arms. Charging it entirely to Luna would be as misleading
as dividing it equally without evidence. The decision rule is:

`Luna saves overall if its additional assignment + acceptance + correction cost
relative to solo is less than $0.732967 on this task.`

The fixture construction and independent audit are shared experimental setup,
not per-arm charges. Nor is it safe to assume real tasks come with this contract
and checker for free. A real solo owner may need less independent review than
our symmetric experimental acceptance procedure.

## Takeaways

This supports a cheap worker owning a settled component through implementation
and development tests, with objective checks and one substantive acceptance
owner. No coordinator duplicated active implementation or corrected its code.
It does not measure spontaneous routing, whole-skill versus no-skill effects,
correction-path success, or reliably cheaper end-to-end work. No operational
skill change was made on the strength of this one pair.

The next measurement should separate acceptance costs by arm while keeping
reviewer, contract, checks and review scope fixed. Preserve this result; do not
retroactively assign its shared review cost. Repeatability and new task domains
remain open. A cheaper reviewer is a different experiment.
