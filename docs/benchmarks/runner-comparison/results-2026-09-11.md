## Why the software arm failed

The earlier smoke test called `scripts/deployment_host.py` from the canonical repo. This comparison copied the scripts into its temporary frozen policy directory and supplied that copied path to the sandboxed coordinator. The sandbox could not open it:

```text
python.exe: can't open file '.../policy/scripts/deployment_host.py': [Errno 13] Permission denied
```

The coordinator stopped and reported not accepted. The host had armed the ticket but received no trigger. There is no worker attempt directory, dispatch record or active worker claim. The harness then stopped the waiting host; it did not retry or start a replacement worker. The original harness raises before writing a software `result.json`, so the separate read-only `postflight.py` preserves the partial accounting without fabricating a normal completion receipt.

Postflight reproduced the access difference with the exact sandbox/workspace profile: the copied script's `--help` failed, while the canonical repo script's `--help` passed. The script bytes are identical. This localizes the failure to the launch location/access boundary; it does not establish a specific underlying ACL rule. No credentials or permissions were changed. Both coordinators also encountered PowerShell working-directory problems; those recoveries remain in their measured costs.

## What this teaches us

The new preflight checked task correctness, coordinator prompt isolation, host authentication and private-state integrity. It did **not** check that the sandbox could execute the exact copied client script. A successful smoke test at one path was insufficient qualification for another path. This is a harness integration failure, not evidence against Luna's accuracy or for/against the runner's cost efficiency.

For the next attempt, use the qualified canonical runtime location and pin its script hashes, while keeping task/policy evidence frozen. Preflight that exact client path and imports from the actual sandbox before paying for a coordinator. Do not change ACLs or copy credentials to force execution. Retain this failed launch cost. A later successful software-only run is a recovered comparison against this native baseline, not the original uninterrupted pair; replication is still required.

No operational routing policy was changed on this result. A cheaper failed launch cannot be reported as a saving, and the native result's roughly 90.5% coordinator share alone does not prove the runner would remove that cost.
