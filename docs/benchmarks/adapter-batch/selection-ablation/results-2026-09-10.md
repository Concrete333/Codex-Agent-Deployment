# Conditional guide loading: results, 10 September 2026

Skipping an unnecessary selection guide worked as instructed, but **did not
reduce total spending in this pair**. Both workflows passed the frozen checks.
The updated-policy workflow needed an additional worker correction after review.

## Change and comparison

The preceding adapter trials supported retaining one worker's ownership through
implementation, tests and corrections, with coordinator review. They also exposed
missing boundary tests and unnecessary loading of the 858-word model-selection
guide despite an explicitly fixed Luna Max assignment.

We made one operational change: read the selection guide only when choosing the
worker or effort; skip it when both are already fixed within allowed
configurations. Ownership, verification, recovery and waiting stayed unchanged.
The repository and installed skill have the same updated entrypoint.

This comparison uses the [version-two fixture and protocol](README.md): six
transaction adapters, 146 visible cases and 98 held-out cases. Its 18 additional
cases cover long CSV fields, malformed long quotes, fixed-width carriage returns
and large JSON numbers in ignored fields. The reference was requalified before
inference; earlier fixtures and results were preserved.

Both conditions required Astra High and exactly one Luna Max worker with
`fork_turns="none"`. Old policy ran first, then conditional read, in fresh
checkouts. Source, acceptance checks, prompts apart from paths, tools and
1,200-second process limits were identical. There was **no solo arm**.

Both exited normally within their process limits and passed protected-file/scope
grading. Effective configurations and one-worker ownership were confirmed from
telemetry. The additional test-method counts are not comparable coverage scores.

Old policy loaded the entrypoint, selection and delegation guides: 2,100 policy
words. Conditional read loaded the entrypoint and delegation guide: 1,253 words.
It did not load the selection guide later. This removed **847 policy words** net
of the longer entrypoint, not 847 total workflow tokens.

Total cost increased **54.6%**, or $0.33899084. The coordinator accounts for 85.9%
of that increase. The new run made one extra pre-wait message and later a
correction handoff; the worker also used more input and output. These observations
explain where the spending occurred, not how much each behavior causally cost.
Neither run exhibited a repeated empty-timeout polling loop.

## Review mattered again

The conditional-read worker initially rejected every bare carriage return in
JSONL, including a whitespace-only line and valid JSON whitespace inside an
object. The contract permits both: physical record separators are LF/CRLF, but
JSON whitespace inside a physical line remains valid.

Astra reproduced the two failures after the 146 visible cases passed. It returned
the defect to the same worker, which removed the blanket rejection and added
regressions for those inputs and invalid CR-separated objects. Astra rechecked
the changes and acceptance tests. This was participant-driven review, with no
evaluator hints. The frozen checker still lacks these specific cases; do not
equate its pass count with exhaustive correctness.

Post-run source inspection found another limitation worth retaining in the
record: the updated run temporarily raises and restores Python's process-global
CSV field limit, whereas the old run uses a local parser. Restoration is present,
but concurrent callers can still observe or interfere with that global setting.
The experiment did not test concurrent use. This is an unmeasured shared-state
risk, not a retroactively added acceptance test or a demonstrated production
failure. No submission or frozen check was changed after grading.

## What follows

Keep conditional loading because the guide provides no selection decision when
model and effort are fixed. Do not advertise it as a measured dollar saving.
Keep meaningful review: it caught another contract defect, and the previous two
team savings already included that responsibility.

There is no evidence here for adding another operational rule. The next coverage
revision can capture the JSONL cases; any concurrent-use requirement should be
explicit before testing it. Further cost claims need repeated, counterbalanced
trials, not a policy change after every noisy result. This old/new-policy pair
does not supersede the earlier solo/team comparisons or test automatic routing.

## Accounting, controls and receipts

and reconciled parent/child counters. Per-million rates for uncached input,
cached input, cache writes and output are Astra $10/$1/$12.50/$50 and Luna
$0.20/$0.02/$0.25/$1.20. No cache writes were reported; reasoning is included in
output. These are API-equivalent estimates, not bills or measured subscription
allowance. Common preparation, supervision and external grading are excluded
and unmeasured, not claimed free.

All frozen input hashes still matched after both runs. Policy snapshots differed
only in the entrypoint's conditional-read bullet; references were identical.
One run per condition, fixed order, and uncontrolled sampling/cache state prevent
