# Adapter batch results — 10 September 2026

The [frozen repeat](results-replication-02-2026-09-10.md) also saved money, but
identified a previously untested large-CSV-field failure in the original reference
and both submissions below. These frozen pass counts remain unchanged; they do
not establish full conformance or include the cost of repairing that later finding.

One required Luna Max worker reduced completed-workflow API-equivalent cost by
**18.4%** against Astra High solo. Both final implementations passed every frozen
external case. This is a positive result for one specified implementation batch,
not evidence of repeatable savings or of the skill choosing delegation correctly.

## Matched pair

Both runs implemented six transaction-import adapters: two CSV formats, JSONL,
XML, fixed-width records and nested JSON batches. They received the same contract,
common normalization helpers, working example, stubs and independent visible
checker. See the [protocol](README.md) and [task](task/TASK.md).

| Condition | Actual configuration | Visible cases | Held-out cases | Added tests | Workflow cost | Elapsed |
| --- | --- | --- | --- | --- | --- | --- |
| A: solo | Astra High; no skill, workers disabled | 140/140 | 86/86 | 10/10 | $1.099710 | 343.41 s |
| D: required worker | Astra High with skill; one Luna Max | 140/140 | 86/86 | 6/6 | $0.89779328 | 818.29 s |

Both completed normally, passed protected-file and edit-scope checks, and needed
no evaluator-fed repair. Added-test counts are test methods with differing
subcases, not comparable coverage scores. Bounded inspection of the final parser
code found no hardcoding or additional contract failure; this is not exhaustive
proof of correctness.

The absolute saving was **$0.20191672**. Delegation took longer; speed was not an
optimization target. The runner's internal `C` label denotes **D** in this report.
There was no unguided or optional-delegation arm in this pair.

The team used **1,744,454 input tokens: 4.96 times solo**, plus 31,476 output
tokens versus 8,205. This was a dollar-cost saving, not a token-count saving.
The coordinator still accounted for 91.4% of team spending.

Astra spending fell by $0.279082. Of that difference, $0.227850 came from fewer
output tokens and $0.051232 from input/cache differences. The worker added
$0.07716528. This is consistent with moving code and test generation to Luna;
the pair does not isolate the causal contribution of individual skill rules.

Costs use the retained rates in [the accounting script](../revision-ab/summarize.py),
per million tokens: Astra $10 uncached input / $1 cached / $50 output; Luna
$0.20 / $0.02 / $1.20. No cache-write tokens were reported, and no response reached
the script's large-input pricing threshold. Reasoning tokens are already included
in output and were not counted twice. Unique own-thread response records reconcile
with cumulative usage for all three participants: 13 responses for A, 14 for D's
coordinator and 27 for its worker. Copied history is not counted as new usage.

These are **API-equivalent estimates, not subscription charges or Codex allowance
measurements**. Common research preparation, supervision and external grading
are excluded. Preparation included one Sol High scaffold/reference author and
independent fixture/checker work by the supervising agent. These costs were not
measured here. Both participants started with those artifacts supplied; this does
not establish savings when specifications and reliable checks must first be built.

## What the agents actually did

The D coordinator spawned exactly one `gpt-5.6-luna` worker at `max`, with
`fork_turns="none"`. The child telemetry confirms that effective configuration.
There were no nested workers, model switches, replacements or Claude calls.
The worker owned all six adapters, shared parsing, regression tests and corrections.

Astra read the checker and common helpers, reviewed the worker's implementation
and tests, and returned two overvalidation defects for correction:

- A valid large JSON number such as `1e999` in an ignored pending-event field was
  rejected. The contract rejects non-standard JSON constants, not valid numbers
  in fields that should be skipped.
- A bare carriage return within a fixed-width memo was rejected instead of
  preserved as data. Only LF and CRLF are physical line separators.

The worker's initial implementation passed all 140 visible cases despite those
defects. The frozen fixtures did not cover these two cases. The coordinator
requested their correction and duplicate-ID regression coverage, then reran checks
and examined the changed helper. Four additional coordinator edge assertions
passed. Thus review had a concrete benefit; deleting it would not preserve the
same correctness evidence.

The coordinator read all seven implementation files and the worker's tests; this
was not a no-reread workflow. It did not write a second implementation or take
over the repairs. One file-integrity assertion initially failed because Git's
index used different newline normalization; the coordinator checked normalized
content and confirmed the protected hashes. That detour is included in cost.

There were two native `wait_agent` calls, covering initial work and the correction
round, under the fixed 25-minute wait configuration. No short polling loop or
worker interruption was observed. The second assignment reused the same worker.

## Controls and limits

The source, fixtures, reference, policy and runner were frozen before inference
and verified unchanged afterward, including the policy copy in D's checkout.
Independent reference qualification passed; stubs and mutations for wrong sign,
dropped records, reversed order, trimmed memo, swallowed errors and checker
tampering failed. Grading was also qualified through the actual read-only sandbox.
Before the trials, the grader was corrected to treat Python's zero-discovered-test
exit as not applicable when optional tests were absent; the initial failed and
corrected preflight receipts were retained. No acceptance cases changed during
or after the model trials.

Both runs used Codex 0.153.4, fresh checkouts, Astra High, standard/default service
tier, the same 1,200-second safety limit, and no automatic retry. A ran first, then
D. Skill discovery and personal context were suppressed; D explicitly read the
324-word entrypoint and its 918-word delegation and 858-word model-selection guides.
The required-worker directive was an additional 41 words. The worker assignment
did not inherit the coordinator's conversation.

This synthetic package favors specified, checkable implementation. There is one
run per condition, no randomized order, no controlled sampling/cache state and no
representative task sample. Held-out cases include 80 valid examples and six
duplicate-ID failures; they are not exhaustive adversarial coverage. Different
solutions and added tests also mean the cost difference is not a pure skill-token
ablation. Required delegation tests the workflow's feasibility, not its routing
judgment or advantage over an unguided team.

The next useful step is replication with the same frozen pair before policy
tuning, followed by a separate optional-routing comparison. Add the discovered
checker gaps in a clearly versioned future fixture, not retrospectively to this
score. Do not weaken review based on this result.
