# Search-scope trial: inconclusive

The portfolio implementation audit identified oversized searches and context
reloading as plausible costs, not a model-routing failure. This trial isolated a
short search-scope instruction before adding it to every worker's context.
All workers used Luna Max; no model orchestrator or reviewer was included.

Total recorded worker cost: **$0.11430**. These use the frozen historical rates
in `revision-ab/summarize.py`, not current prices, bills or subscription usage.
Preparation, this supervising conversation and offline checks are excluded.
Interrupted in-flight usage may be missing; the last cell is not a completed
cheap result. There was one attempt per cell, no worker retry or correction.

Fees B was about 11.4% cheaper than A, but used more responses and more captured
tool-output text (70,171 vs 60,643 characters). Neither fee run compacted or had
an explicitly truncated tool return. These measurements do not establish an
improvement in retrieval. There is no valid second completed pair.

## Why the comparison stopped

Saved traces showed PowerShell starting at `C:\` despite an explicit checkout
working directory. A relative file search consequently traversed outside the
intended corpus and returned access-denied diagnostics. Explicitly changing to
the checkout also failed. A no-model sandbox probe reproduced this with the
worker's edit profile and with read-only access; changing slash spelling did
not fix it. The exact underlying Windows access cause remains unresolved.

This violates the intended search scope and contaminates costs. The final
worker was stopped, its blocked receipt retained, and no further paid cells
were launched. The successful objective inventories do not remove this confound.

Fees B separately exposed a runner exception: validating a sandbox-created
scratch artifact's path raised PermissionError before the existing sandbox
hash fallback could run. Offline recovery used the existing read-only hash
helper and frozen checker. Both claimed artifacts had unchanged hashes before
and after the exact 14-row check. The original blocked receipt was preserved;
offline recovery is not silently counted as an ordinary runner pass.

## Changes made after stopping

- Added a no-model Windows shell-cwd preflight before worker launch. Unexpected
  location, empty output or shell failure blocks the run. It does not change
  ACLs, disable the sandbox or use a model to repair directory access.
- Extended the read-only artifact-hash fallback to cover PermissionError during
  path validation as well as during file reading. Relative-path containment and
  complete hash-set validation remain required.
- Kept operational routing and worker-packet wording unchanged. This test does
  not justify adding the proposed paragraph to every assignment.

Validation: 101 runner/wrapper tests and three oracle tests passed. The repaired
hash function reproduced both saved artifact hashes. Live no-model preflight
rejected the affected fixture and passed in the canonical repository.
These are runtime fixes, not measured model-cost savings. The installed runner
was synchronized only after validation; the pre-fix version is retained with
the private trial evidence. The frozen manifest and original receipts remain
unchanged.

## Next useful comparison

First qualify a fresh isolated checkout with the actual shell-cwd probe, not
just an absolute-path grader. Then repeat the same packet ablation with new
identities and frozen evidence before adopting extra prompt text. No additional
paid rerun was performed here.

For portfolio-sized implementation, the next separate hypotheses are focused
resumption after compaction, and keeping caller/test corrections with their
component owner. Test one change at a time with fixed models and independent
acceptance. This syntax-inventory task cannot establish either benefit, whole
skill savings, or unchanged implementation accuracy.
