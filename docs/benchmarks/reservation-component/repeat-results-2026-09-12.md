# Frozen reservation repeat

Both workers were accepted again. The guided arm cost **13.3% less** in this
repeat, closely matching the first pair. The measured advantage remains small
in absolute terms, and live research supervision cost much more than either
worker. No operational skill change was made.

## Same comparison, new identities

`repeat.py` verified the original source, specification, evaluator, reference,
runner and accounting hashes before preparing fresh checkouts. It compared the
two new requests with the originals: only IDs and private paths differed.
All nine qualification variants had the expected outcomes and both actual
shell-cwd preflights passed. No prior worker answers or tests were copied.

The [original protocol](README.md) was retained: B then A, Luna Max, the same
tools and Python interpreter, 1,200-second limits, one possible Sol High repair
per failed arm. No new fixture-audit model was called. Both passed their initial
host checks, so no repair session ran. This is not a new ownership experiment,
solo baseline, spontaneous routing test or full-skill ablation.

## Acceptance review

Both passed the unchanged independent suite, including its 100-operation
sequence. The host then revalidated receipt/artifact hashes, ran the additional
worker tests in a read-only sandbox, and read all changed source and test files.

Both implementations use the shared core for preview, stage changes before
commit, preserve exact identities and public imports, and isolate journal rows
from returned data. No material contract issue was found. Each changed only
the three intended source files and added one permitted test file. Protected
files stayed unchanged and handoffs listed every changed artifact. No new
acceptance criterion or evaluator-fed correction was introduced after seeing
the results. Passing this fixture is not proof over every possible input.

## Common supervision overhead

A separate snapshot of this supervising task's current turn, taken through the
last recorded event at **2026-09-12 17:14:02 UTC**, captured:

- Astra High: 19 completed response records.
- 3,265,086 input tokens, including 3,202,560 cached input tokens.
- 13,406 output tokens, including 9,094 reasoning tokens.
- **$4.49812 historical API-equivalent** at the same frozen accounting basis.

This is a point-in-time subtotal, not a final complete bill. It excludes later
and in-flight responses, prior preparation turns and the workers. It includes
this turn's setup, reading, waiting, review and accounting work; it must not all
be attributed to idle polling. The snapshot is saved separately and is not
allocated between the A/B arms.

Even that captured subtotal is much larger than the two workers combined.
The comparison therefore supports a worker-level result, not cheaper end-to-end
live research. Host-run checks and inspection are also outside worker token
costs. Future batches should run without keeping an expensive model actively
supervising, then return a compact completed report for one review. The existing
software driver can run independently; launching it from a live model does not
itself remove the model's outer waiting and update costs.

## Decision and next step

Retain the current short search guidance without expanding it into more rules.
Two repeats on one small synthetic component are encouraging, not a general
savings guarantee. Both ran B first; order/cache effects and model sampling
remain uncontrolled. Neither needed external repair, so live correction-path
effectiveness is still unmeasured.

The next priority is measuring a host-managed batch with one post-completion
review, including that review cost, on a more substantial held-out component.
Do not add more model-owned checkpoints to save fractions of a cent per worker.
