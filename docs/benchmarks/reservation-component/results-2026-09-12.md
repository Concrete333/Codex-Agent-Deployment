# Reservation component: both accepted, guided arm cheaper in this pair

The search-guided Luna Max worker completed this previously untested component
task for **$0.03377**, versus **$0.03897** for the control: **13.4% lower recorded
worker cost**. Both passed the same independent acceptance suite and source
review without an external correction. This is one paired observation, not a
general savings rate.

## What ran

See the [frozen procedure](README.md) and [task contract](task/SPEC.md).
Two isolated copies of a 6,196-byte synthetic service/spec/public-test fixture
started with a non-atomic reservation loop and commit-only API. Workers added
atomic batching, duplicate aggregation, validation, preview and caller routing.

- **B first:** bounded assignment plus the exact search paragraph previously
  tested on source inventories.
- **A second:** identical assignment without that paragraph.
- Both used **Luna Max**, the same CLI, tools, working Python interpreter,
  contract, initial files, independent checker and 1,200-second safety limit.
- Both owned the entire component and their development tests. Neither read
  the deployment skill itself; this tests assignment wording, not autonomous
  orchestration or skill discovery.
- A predeclared single Sol High repair was available after failed acceptance.
  Neither arm needed it. The external correction path remains untested live;
  its dispatch bounds and exact-feedback behavior passed four offline tests.

The first offline fixture was superseded before any participant ran after an
independent Sol High audit found an import-alias overconstraint. Both valid
reference styles then passed, and the starter plus six consequential mutants
failed. Both real checkout shell-cwd preflights passed. No task/checker/prompt
changes were made between participant runs. No live Spaceships files changed.

## Acceptance beyond test counts

The independent suite includes four public and twelve hidden test methods,
with validation subcases and a deterministic 100-operation sequence. It checks
tenant separation, exact identities, aggregation/order, strict types, rollback,
single-use iterators, preview, journal isolation and request dispatch.

After completion the host revalidated receipts and artifact hashes, inspected
all three changed source files and added tests, and ran only the additional
worker tests in the read-only sandbox. Both results:

- Route preview through the shared `reserve_batch(..., dry_run=True)` function.
- Finish validation/aggregation and availability checks before stock mutation.
- Preserve public imports and copy immutable-valued result rows into independent
  journal lists/dicts; returned-data mutation cannot alter earlier entries.
- Change only `reservation/core.py`, `service.py`, `api.py`, and add one permitted
  worker-test file. Protected files and hashes through checking stay unchanged.
- List every changed source/test file in the handoff. No material contract gap
  was found in source review. This is not a proof over every possible input.

The handoffs' statements that the independent check was pending are superseded
by the saved passing host-check receipts, not accepted as evidence themselves.

## Development errors are included

**A** initially launched test files directly, causing `ModuleNotFoundError` for
the package. It recovered with root-based unittest discovery.

**B** initially wrote a wrong expected value in its preview test: after a commit
left four units, it expected preview of one more reservation to report four
remaining instead of the contract's proposed three. It corrected its own test;
the independent contract and checker were unchanged.

Both costs include these development corrections. Thus “first-attempt accepted”
means no failed external acceptance and no extra worker session, not an error-free
implementation process. Different local mistakes, cache behavior and sampling
make the exact cost difference noisy. No costs were removed after seeing results.

## Takeaways

The guided arm was cheaper without an observed acceptance loss, consistent with
the two earlier inventory pairs. The mechanism is less clear here: tool-output
text fell only 4.8%, neither worker truncated output, and part of the dollar
difference comes from cached versus uncached input and generated reasoning.
Do not label the entire 13.4% as reduced search or orchestration overhead.

Keep the existing short search guidance. **No additional operational skill
wording or model-routing change was made from this single pair.** It does not
show that Luna is suitable for open-ended implementation, that a cheaper
reviewer preserves accuracy, or that delegation beats solo work.

The next useful step is a fresh repeat of this frozen pair before adding another
intervention. A further task can test caller/test ownership or checkpoint
recovery separately; neither was varied here. Supplying a known development
test command is a plausible way to avoid A's launcher error, but was not tested
as a separate treatment and is not claimed as a measured saving.
