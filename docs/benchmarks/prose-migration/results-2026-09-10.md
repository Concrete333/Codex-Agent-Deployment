## Task and controls

The agent reviewed 50 independent, synthetic Harbor 4.0 issue discussions and
release-note excerpts: **12,907 words / 95,658 source bytes**. Each asked whether
one proposed operator action was required for a supported production 3.x-to-4.0
upgrade. Records included later corrections, withdrawals, conditional scope and
unresolved policy. The source-only reviewed key contains 12 universal, 18
conditional, 13 no-action and 7 unresolved decisions.

The output contract required every ID once, a precise explanation of action and
scope, and concise exact quotations with line citations. Scripts and searches
were allowed. Neither task prompt instructed the participant to delegate or
named a preferred worker. The skill was unchanged from the previous evaluation.

Execution was sequential A then C, using Codex CLI 0.153.4, Astra High, Python
3.13, the same starting tree and a 2,700-second safety cutoff. C had native
Luna/Terra/Sol and authorized Opus 5 access through the frozen wrapper; its
operational policy excluded Astra and Fable workers. A had delegation disabled.
Personal skill discovery, plugins and memory were suppressed as in earlier runs.
Prompts showed no discovered skill catalogue or answer-key fields. The explicit
deployment policy was present only in C.

The grader and author reference were exercised through the actual read-only
sandbox before launch. Six mutants were rejected: missing record, wrong
disposition, fabricated quote, invalid line, wrong date and changed source.
All frozen input hashes still matched after both runs. No grader, corpus,
answer key, task or operational policy changed during the pair.

## Accuracy beyond the automated score

Both answers passed ID coverage/order, date/release, schema, length limits,
disposition, exact quotation/line validity and source-preservation checks.
The evaluator also reviewed all 100 explanations and their quotations against
the source, not just the correct category labels.

That [semantic review](semantic-review.md) found the same scope problem in
ISSUE-016 in both answers. Their opening instruction requires catch-up for
"synchronous or failover replicas", while the later authoritative clarification
makes eligibility to become the primary the deciding property, not transport
mode. Both even quote that clarification, but do not fully reconcile their
opening wording with it. The condition should be failover-eligible replicas.

No material action/scope issue was found in the other 49 records per answer.
This is an unblinded model review, not independent human adjudication or proof
that all other wording is perfect. Both saved answers need the same correction
for unqualified semantic acceptance. Neither was corrected or rerun. The
automated pass must not be reported as perfect factual accuracy.

## What C actually did

C loaded `SKILL.md`, chose local review, and did not load the model-selection or
Claude CLI guide. It read the source corpus, wrote its own answer, and checked
it locally. Both runs' usage trees contain only their Astra High root. There
were no spawn, wait, sleep, interruption or handoff calls, and no Claude worker
invocations or receipts.

This did not reproduce an expensive orchestration loop: C made **one fewer**
model response than A. It simply did not try cheap-worker execution. Its public
commentary says it is reviewing locally; it does not provide a quantified
comparison of worker plus verification cost against solo work. The trace does
not establish that declining delegation was economically optimal.

## Setup cost and inspection

The separate Sol High fixture-authoring worker used 809,246 input tokens,
762,368 cached input tokens and 32,856 output tokens across 18 responses:
**$1.1495792 API-equivalent**, reconciled from its own telemetry. It was not a
participant worker. Corpus authoring plus the two participants total
$3.7744412 by this measure, **excluding** coordinator preparation, source review,
supervision and offline evaluation. The full experiment cost is therefore
higher; setup is not free or part of a claimed task saving.

Host reads of sandbox-created answer files were denied. Evaluation inspected
them through the existing read-only sandbox identity with an explicit Python
executable. No ACL changes, participant edits or additional model calls were
needed for that access. Answer hashes stayed stable during review.

## Takeaway and next diagnostic

This was a more plausible cheap-reader workload than the earlier scriptable
catalogue, but the hoped-for delegation was **not observed**. It cannot tell us
whether Luna would preserve accuracy or reduce total task cost. The skill's
early local-work decision happened before consulting model-selection guidance.

Do not keep enlarging or redesigning synthetic tasks until the skill chooses a
worker. The next useful diagnostic is a separately authorized, explicitly
delegated control on this **same frozen corpus**: Astra High assigns one Luna
Max worker the complete checklist, then performs normal bounded verification.
Count both agents and corrections and apply the same full external review.
That distinguishes worker viability from automatic routing. It would not be a
fair claim that the unmodified skill spontaneously chose that strategy.

No forced-worker control or repeat was run in this turn. One pair is diagnostic,
not a statistically reliable result. The corpus is synthetic and relatively
regular; its early cases often have conspicuous authoritative statements. It is
routine prose review, not a representative large-repository or research workload.
