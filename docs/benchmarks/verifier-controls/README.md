# Consequential-error verifier pilot

Compare one Sol High review and one Opus 5 Low review of the same new, blinded
source/draft packet. This is a worker qualification diagnostic, not a solo/team
comparison or a causal test of the skill amendment. The policy change is one
sentence: resolve worker-flagged judgments against sources before accepting them.

## Frozen design

Twelve fictional release records: six consequential errors (deadline, authority,
scope, units, ordering and polarity) and six clean controls. Three errors and
three controls carry worker-flagged judgment calls. The same flags appear in
both packets; a flag does not imply a defect.
Sources include superseded proposals, exceptions and later non-authoritative
comments. Controls include an optional action, a settled conditional requirement
and literal brackets/ellipsis. No external facts are needed.

Participants receive only TASK.md, draft.json and sources/ in fresh directories.
They do not receive this file, cases.json, the key, class balance, error types,
prior reviews or a target finding count. Both receive identical prompts and
assignment data. The author/evaluator knows the key. A separate Luna Max agent
audits all labels and quoted evidence before trials; this is preparation, not a
third scored reviewer. Instruction-constrained separation is not adversarial
filesystem isolation.

Sol uses the previous native read-only Codex runner configuration; Opus uses the
existing review-profile wrapper (Read/Glob/Grep, no shell, five-minute caching).
Different system prompts, toolsets and provider runtimes remain confounders.
There are no nested workers, retries, repairs or hints. Each has a 600-second
process limit; Opus also has a $3 API-estimate cap, not an allowance ceiling.
Sol runs first. No claim of randomized sampling or cache control.

Preflight verifies gold quotations, exact clean/defect counts, packet identity,
structural grading mutations, read access, hidden-key/skill exclusion in Codex
prompt inspection, wrapper arguments, local subscription authentication and
runtime versions. Hash all trial scripts, cases, prompt, input files, policy and
wrapper before inference. Do not edit frozen material after starting.

## Scoring fixed before inference

For every record require accept/changes_needed and evidence-backed findings.
Count a true positive only when the review identifies the seeded action error
with valid source evidence, a materially accurate impact and a suitable
correction. Merely naming the affected ID is insufficient. Wrong allegations on
defective records do not count as detection and are recorded separately.

Report detected errors and misses out of six, clean records falsely challenged
out of six, and any additional unsupported findings. Read every finding against
the fixed source/key before finalizing the mechanical verdict-based score. A
clean record with an unsupported material allegation is a false alarm. Missing
coverage, invalid output or process limits remain incomplete, not a clean pass.
Do not silently repair a review or change gold to fit it. Key disputes must be
reported and, if genuine, invalidate that item symmetrically.

Offline qualification exercises perfect, accept-all, reject-all, omitted-record,
fabricated-quote and wrong-quote-on-right-ID reviews. These are checker tests, not
reviewer outcomes. Exact quotations establish provenance, not entailment.

Measure complete reviewer-session API-equivalent cost, including tools/context
and helper calls where reported. Keep preparation, independent key audit,
supervision and external adjudication separate and do not claim them free.
Do not conflate output reasoning with an additional output category or list-price
estimates with subscription allowance. Record effective configurations when
exposed; unavailable effort telemetry is unknown, not proof.

## Interpretation and use

One short synthetic packet per configuration can expose basic failures, not
establish production reliability, accuracy equivalence, or accepted-workflow
savings. Passing obvious errors does not erase previous subtle-error misses.
Future tests need independently authored harder cases, clean-only packets and
repeated/counterbalanced runs before promoting a cheaper verification owner.

`experiment.py prepare` and `preflight` are offline (version/auth checks are not
inference); `run` launches each paid reviewer once; `summarize` checks outputs and
reconciles telemetry. The ignored local locator retains receipt paths. Never
load the key or result reports in future participant contexts.
