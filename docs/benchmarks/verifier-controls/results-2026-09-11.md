## What changed and what was tested

The repository and installed skill now both say:

> Resolve worker-flagged judgment calls against the source before accepting affected claims; relaying them is not verification.

That sentence was inserted into the existing substantive-verification paragraph.
No new entrypoint text, model default or automatic reviewer was added. Research
and results remain outside operational context.

The [frozen protocol](README.md) defines twelve new fictional release records,
with six materially wrong operator instructions and six clean controls. Three
records in each group carry a worker-flagged judgment call. The same packet and
prompt went to both reviewers in fresh sessions; neither received the answer
key, error count, previous failures or this report. No hints or retries were sent.

The key was [independently checked by a separate Luna Max preparation agent](key-audit.md).
Its two wording caveats were resolved before the final freeze. Offline checks
qualified packet identity, source/draft quotations, complete coverage, all-accept
and all-reject mutations, fabricated evidence and literal punctuation. The
checker deliberately does not pretend to determine semantic support.

This is an easier and shorter diagnostic than the previous 50-discussion task.
Sources state the governing action explicitly and the planted errors change
required action, not just an explanation of an unresolved proposal. It tests
basic detection with clean controls; it is not an equivalent repeat of ISSUE-040.

## Final adjudication

The author/evaluator read all findings against the frozen sources and key.
Both reviewers gave one valid finding on each defective record and none on the
controls. Their quotations were verbatim, impacts materially supported and
corrections suitable. There were no disputed labels or post-result key changes.

| Record | Error that both identified | Evidence/correction check |
| --- | --- | --- |
| NOTE-102 | Seven-day deadline instead of 72 hours | Both cite the final 72-hour expiry and correct the deadline. |
| NOTE-104 | Rejected production key-validation bypass | Both require stopping and restoring connectivity, not using the prototype flag. |
| NOTE-105 | Exemption for asynchronous promotion candidates | Both require all promotion candidates to catch up. |
| NOTE-108 | 90 milliseconds instead of 90,000 | Both identify the unit conversion and correct the value. |
| NOTE-109 | Delete the old recovery copy before validating its replacement | Both retain it until a successful isolated restore is recorded. |
| NOTE-111 | Stable/unstable import restart rule reversed | Both allow restart only with the stable-version guarantee and require other imports to finish. |

Clean controls 101, 103, 106, 107, 110 and 112 were accepted. Flagged clean records
were not treated as necessarily defective. All three unflagged errors were also
found, so neither result was merely a response to the worker flags. The explicit
per-record decisions plus observed source reads support coverage; the absence of
written commentary on accepted flags does not expose the reviewers' internal
reasoning or independently prove how each judgment was resolved.

The sanitized full reviews are saved beside this report:
[Sol](review-sol-high.json) and [Opus](review-opus-low.json). They contain evaluation
answers and must stay out of future participant context. Final adjudication is an
unblinded model evaluation, not independent human ground truth.

## Accounting and runtime checks

Sol used `gpt-5.6-sol/high` in native Codex 0.153.4. It made three responses and
two shell calls: reading the task/draft and then every source. Own-thread usage
reconciles to 31,406 input tokens, including 18,816 cached, and 2,163 output tokens,
including 829 reasoning tokens. No worker was spawned. At the existing benchmark
rates ($4/M uncached input, $0.40/M cached input, $20/M output), cost is $0.1011464.

Opus used `claude-opus-5/low` through the existing read-only wrapper in Claude Code
2.1.266. The saved session explicitly records `effort: low`; model usage reports
Opus 5 plus the internal Haiku helper. It read TASK.md, draft.json and all twelve
sources, with no shell, delegation, permission denial or reported error. Five-minute
cache writes were confirmed: 66 uncached input, 9,566 cache-write input, 16,332
cache-read input and 3,024 output tokens (including 115 thinking). Provider-reported
list-price cost is $0.1438835 for Opus plus $0.000992 for Haiku = $0.1448755.

The two reviews total **$0.2460219**. The independent Luna Max key audit adds
**$0.02835976**, separately reconciled: **$0.27438166 in those three measured
sessions**. This excludes the primary agent's fixture design, supervision and
adjudication, and external checks. Those costs were not measured, not assumed
free. These figures are not subscription-allowance measurements or invoices.

Both reviewer processes completed inside the 600-second limit (Sol about 59 s,
Opus about 33 s). Opus's $3 API-estimate safety cap was not approached. All frozen
hashes matched after execution. Provider toolsets, system prompts and inherited
context differ: Codex used the previous isolated configuration; the Claude wrapper
disabled settings sources/MCP/skill discovery but can still inherit global Claude
instructions. Its observed tool calls stayed within the task. This is a comparison
of these configured routes, not an equal-token or identical-runtime model test.

## What to do with the result

Keep both configurations as candidates for this clear source-backed error class.
Do not add an always-on reviewer or promote either to sole semantic verifier on
the strength of six detections. Their previous subtle-error misses still stand.
No further model-routing change is justified by this pilot.

Before relying on cheap review for acceptance, test independently authored cases
with longer context, consequential errors that are less directly contradicted,
clean-only packets and realistic error prevalence. Repeat and counterbalance
runs. Count false alarms and their correction/adjudication cost as well as misses.
Only then test the whole ownership/review workflow against local acceptance.
